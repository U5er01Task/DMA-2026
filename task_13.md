## 1. Философия Flutter: Архитектура трех параллельных деревьев

В традиционных UI-фреймворках (Android XML, iOS UIKit, DOM) элементы интерфейса мутируют напрямую через вызовы методов (например, `button.setText("Новый текст")`).

Во Flutter применен **декларативный подход**: пользовательский интерфейс является чистой функцией от текущего состояния приложения:
\[ UI = f(State) \]

Чтобы интерфейс работал с частотой 60–120 кадров в секунду, фреймворк поддерживает **три параллельных дерева**:

```
 ┌──────────────────────┐    ┌──────────────────────┐    ┌──────────────────────┐
 │     WIDGET TREE      │    │     ELEMENT TREE     │    │  RENDEROBJECT TREE   │
 ├──────────────────────┤    ├──────────────────────┤    ├──────────────────────┤
 │ Декларативная        │    │ Скелет приложения,   │    │ Низкоуровневая       │
 │ конфигурация ("План")│    │ управляющий          │    │ геометрия, размер,   │
 │ • Неизменяемый       │    │ жизненным циклом     │    │ расчет хит-тестов    │
 │ • Создается и        │    │ • Живет долго        │    │ и отрисовка GPU      │
 │   уничтожается       │    │ • Связывает Widget   │    │ • Дорогой в создании │
 │   миллисекунды       │    │   с RenderObject     │    │ • Мутирует только    │
 │ • Дешевый в создании │    │ • Хранит State       │    │   при необходимости  │
 └──────────┬───────────┘    └──────────┬───────────┘    └──────────┬───────────┘
            │                           │                           │
            ▼                           ▼                           ▼
    ContainerWidget ────────►   ContainerElement  ────────►   RenderPadding
            │                           │                           │
            ▼                           ▼                           ▼
       TextWidget   ────────►     TextElement     ────────►    RenderParagraph
```

### Алгоритм сверки (Reconciliation Algorithm)

Когда вызывается метод `build()`, Flutter сравнивает новый `Widget` со старым `Element` в той же позиции:

1. Если `widget.runtimeType` и `widget.key` совпадают: `Element` просто обновляет свою ссылку на новый `Widget` и перенастраивает существующий `RenderObject` без его пересоздания.
2. Если тип или ключ изменились: старый подграф деревьев уничтожается (`unmount`), и создается новый.

## Тема 1. StatelessWidget: декларативная неизменяемость и декомпозиция

`StatelessWidget` описывает часть интерфейса, которая зависит **исключительно** от конфигурационных параметров, переданных в его конструктор, и от контекста (`BuildContext`).

### Правило абсолютной неизменяемости

Все поля класса `StatelessWidget` **обязаны быть `final`**. Виджет не имеет внутреннего изменяемого состояния.

```dart
import 'package:flutter/material.dart';

class UserBadgeCard extends StatelessWidget {
  final String userName;
  final String role;
  final bool isOnline;
  final VoidCallback? onTap;

  // Константный конструктор с обязательным super.key
  const UserBadgeCard({
    super.key,
    required this.userName,
    required this.role,
    this.isOnline = false,
    this.onTap,
  });

  @override
  Widget build(BuildContext context) {
    // Метод build должен быть чистой функцией без побочных эффектов!
    return InkWell(
      onTap: onTap,
      borderRadius: BorderRadius.circular(12),
      child: Container(
        padding: const EdgeInsets.all(16),
        decoration: BoxDecoration(
          color: Colors.white,
          borderRadius: BorderRadius.circular(12),
          border: Border.all(color: Colors.grey.shade300),
        ),
        child: Row(
          children: [
            CircleAvatar(
              backgroundColor: isOnline ? Colors.green : Colors.grey,
              radius: 6,
            ),
            const SizedBox(width: 12),
            Column(
              crossAxisAlignment: CrossAxisAlignment.start,
              mainAxisSize: MainAxisSize.min,
              children: [
                Text(userName, style: const TextStyle(fontWeight: FontWeight.bold)),
                Text(role, style: TextStyle(color: Colors.grey.shade600, fontSize: 12)),
              ],
            ),
          ],
        ),
      ),
    );
  }
}
```

> [!TIP]
> **Принцип декомпозиции:** Никогда не пишите экраны с глубиной вложенности в 200 строк. Разбивайте экран на десятки маленьких, независимых `StatelessWidget` с константными конструкторами. Это позволяет Flutter пропускать перерисовку неизменившихся поддеревьев.

### Задания для закрепления

1. **Карточка курса со скидкой:** Спроектируйте `StatelessWidget`, принимающий название курса, имя преподавателя, старую цену и новую цену.
2. **Индикатор сетевого статуса:** Создайте компактный виджет с иконкой и текстом «Онлайн / Офлайн» на основе одного булевого флага.
3. **Кнопка с иконкой и текстом:** Напишите кастомную кнопку, принимающую иконку `IconData`, текст и колбэк нажатия `VoidCallback`.
4. **Рефакторинг вспомогательного метода в виджет:** Возьмите код, где верстка вынесена в метод `Widget _buildItem()`, и перепишите его в отдельный `StatelessWidget`, объяснив выигрыш в оптимизации.
5. **Тестирование константности:** Проверьте через инструмент Flutter Inspector в IDE, как добавление ключевого слова `const` перед виджетом блокирует его повторный вызов `build()`.

## Тема 2. StatefulWidget и исчерпывающий жизненный цикл State

`StatefulWidget` используется, когда интерфейс должен динамически меняться в ответ на действия пользователя, таймеры или ответы сети.

### Архитектура разделения на два класса

1. `StatefulWidget` — неизменяемая конфигурация (создается заново при каждом изменении родителя).
2. `State<T>` — долгоживущий изменяемый объект состояния (сохраняется в `Element Tree` между перерисовками).

### Диаграмма жизненного цикла State

```
            Создание виджета: StatefulWidget()
                           │
                           ▼
                     createState() ◄── Создает объект State
                           │
                           ▼
                      initState()  ◄── Однократная инициализация контроллеров/подписок
                           │
                           ▼
              didChangeDependencies() ◄── Реакция на изменение InheritedWidget (Theme/Locale)
                           │
            ┌──────────────┴──────────────┐
            │                             │
            ▼                             ▼
    [ setState() ]                 [ Новые параметры ]
            │                             │
            │                             ▼
            │                   didUpdateWidget() ◄── Сравнение oldWidget и widget
            │                             │
            └──────────────┬──────────────┘
                           │
                           ▼
                        build() ◄── Формирование дерева виджетов (вызывается часто!)
                           │
                           ▼
                      deactivate() ◄── Виджет временно удален из дерева
                           │
                           ▼
                       dispose() ◄── Окончательное уничтожение: отписка от стримов,
                                       закрытие контроллеров (Устранение утечек памяти!)
```

### Пример реализации интерактивного счетчика

```dart
class AnimatedCounterWidget extends StatefulWidget {
  final int initialValue;
  final ValueChanged<int>? onCountChanged;

  const AnimatedCounterWidget({
    super.key,
    this.initialValue = 0,
    this.onCountChanged,
  });

  @override
  State<AnimatedCounterWidget> createState() => _AnimatedCounterWidgetState();
}

class _AnimatedCounterWidgetState extends State<AnimatedCounterWidget> {
  late int _count;

  @override
  void initState() {
    super.initState();
    // Инициализация внутреннего состояния данными из виджета
    _count = widget.initialValue;
  }

  @override
  void didUpdateWidget(covariant AnimatedCounterWidget oldWidget) {
    super.didUpdateWidget(oldWidget);
    // Если родительский виджет передал новое начальное значение
    if (oldWidget.initialValue != widget.initialValue) {
      _count = widget.initialValue;
    }
  }

  void _increment() {
    setState(() {
      // Только синхронное изменение полей состояния!
      _count++;
    });
    // Уведомление внешнего слушателя
    widget.onCountChanged?.call(_count);
  }

  @override
  void dispose() {
    // Очистка таймеров, контроллеров и слушателей
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return ElevatedButton(
      onPressed: _increment,
      child: Text('Нажато раз: $_count'),
    );
  }
}
```

> [!CRITICAL]
> **Золотое правило `setState()`:** Внутри колбэка `setState(() { ... })` запрещено выполнять асинхронные операции (`await`, сетевые запросы, чтение файлов). Внутри меняются **только** локальные переменные!

### Задания для закрепления

1. **Таймер на базе StatefulWidget:** Создайте виджет секундомера, запускающий `Timer.periodic` в методе `initState()` и обязательно отменяющий его в `dispose()`.

4. **Поле ввода с TextEditingController:** Создайте форму ввода текста, где контроллер инициализируется в `initState()`, а в `dispose()` вызывается `controller.dispose()`.

## Тема 3. BuildContext: навигация по дереву и поиск предков

`BuildContext` — это не просто абстрактный токен, это **сам объект `Element`**, реализующий интерфейс контекста. Он определяет точное положение виджета в общем дереве элементов.

### Поиск предков по дереву (InheritedWidgets)

Через контекст виджет может запрашивать данные у своих родителей выше по дереву:

- `Theme.of(context)` — получение текущей цветовой темы.
- `MediaQuery.sizeOf(context)` — получение физических габаритов экрана.
- `ScaffoldMessenger.of(context)` — вывод всплывающего SnackBar.

```
       AppRoot (MaterialApp)
             │
      ScaffoldElement (Предок)
             │
    ┌────────┴────────┐
    ▼                 ▼
 AppBar            MyBodyElement (Потомок ищет Scaffold выше по дереву)
```

### Классическая ошибка новичка с контекстом

Попытка вызвать `Scaffold.of(context)` в методе `build()`, где сам `Scaffold` объявляется в этом же методе:

```dart
// ❌ ОШИБКА: context еще НЕ знает о Scaffold, так как находится ВЫШЕ него в дереве!
Widget build(BuildContext context) {
  return Scaffold(
    body: ElevatedButton(
      onPressed: () => Scaffold.of(context).openDrawer(), // CRASH!
      child: const Text('Открыть меню'),
    ),
  );
}

// ✅ ПРАВИЛЬНО: Использование виджета Builder для создания нового подконтекста!
Widget build(BuildContext context) {
  return Scaffold(
    body: Builder(
      builder: (BuildContext innerContext) {
        return ElevatedButton(
          // innerContext находится СТРОГО ВНУТРИ Scaffold!
          onPressed: () => Scaffold.of(innerContext).openDrawer(),
          child: const Text('Открыть меню'),
        );
      },
    ),
  );
}
```

### Задания для закрепления

1. **Динамический цвет от темы:** Окрасьте контейнер в первичный цвет текущей темы через `Theme.of(context).colorScheme.primary`.
2. **Определение ориентации через MediaQuery:** Выведите на экран надпись «Альбомная» или «Портретная», используя свойство `MediaQuery.orientationOf(context)`.
3. **Показ SnackBar через ScaffoldMessenger:** Напишите кнопку, которая по клику отображает снизу информационное сообщение со временем нажатия.
4. **Использование виджета Builder:** Создайте экран со шторкой `Drawer` и откройте ее программно по клику на кнопку в центре экрана через подконтекст `Builder`.
5. **Поиск ближайшего родительского стейта:** Найдите ближайший стейт формы через `Form.maybeOf(context)` и выполните валидацию полей.

## Тема 4. Ключи (Keys): сохранение состояния в динамических структурах

В большинстве случаев Flutter справляется без явных ключей. Однако, когда в списке **изменяется порядок элементов**, удаляются строки или фильтруется коллекция элементов, обладающих собственным состоянием (`StatefulWidget`), отсутствие ключей приводит к критическим багам.

### Когда ключи необходимы?

Когда виджеты одного типа меняются местами или удаляются из динамической коллекции.

```
Без ключей: Flutter ориентируется ТОЛЬКО на позицию в дереве.
При удалении первого элемента Element Tree сохраняет старый стейт и ошибочно привязывает его ко второму элементу!
```

### Разновидности ключей

| Тип ключа              | Назначение                                            | Типичный сценарий                        |
| :--------------------- | :---------------------------------------------------- | :--------------------------------------- |
| `ValueKey('id_123')`   | Ключ на основе примитива (число, строка)              | Строки списков товаров, элементы корзины |
| `ObjectKey(userModel)` | Ключ на основе эквивалентности объекта                | Сложные сущности базы данных             |
| `UniqueKey()`          | Генерирует уникальный несовпадающий идентификатор     | Принудительный сброс анимации или стейта |
| `GlobalKey<T>()`       | Глобальный ключ доступа к State из любой точки дерева | Валидация форм `GlobalKey<FormState>()`  |

```dart
// Пример использования ValueKey в динамическом списке
ListView.builder(
  itemCount: items.length,
  itemBuilder: (context, index) {
    final item = items[index];
    return TodoItemTile(
      key: ValueKey(item.id), // ГАРАНТИЯ сохранения чекбокса за конкретной задачей!
      item: item,
      onDelete: () => removeItem(item.id),
    );
  },
);
```

> [!WARNING]
> `GlobalKey` — самый тяжелый инструмент во Flutter. Он нарушает локальность дерева представлений. Используйте его только для управления состоянием форм `FormState` или вычисления абсолютных глобальных экранных координат виджета.

### Задания для закрепления

1. **Эксперимент со сдвигом стейта:** Создайте список из двух цветных плашек со случайным цветом в `initState()`. Поменяйте их местами в списке без `Key` и зафиксируйте баг с сохранением цветов на старых местах.
2. **Исправление бага через ValueKey:** Добавьте `ValueKey` к элементам из первого задания и убедитесь, что цвета стали перемещаться вместе с карточками.
3. **Управление формой через GlobalKey:** Создайте форму `Form` с валидацией поля email и выполните проверку `formKey.currentState!.validate()` по кнопке.
4. **Сброс стейта через UniqueKey:** Создайте виджет таймера и перезапустите его состояние с нуля путем генерации нового `key = UniqueKey()`.

## Тема 5. Базовый анатомический каркас: MaterialApp и Scaffold

Любое визуальное приложение начинается с конфигурации корневого виджета приложения и скелета конкретного экрана.

### Роль MaterialApp

- Задает глобальную тему оформления приложения (`theme`, `darkTheme`).
- Настраивает навигацию и генерацию маршрутов (`routes`, `onGenerateRoute`).
- Подключает локализацию и языковые пакеты (`localizationsDelegates`).

### Анатомические слоты Scaffold

`Scaffold` реализует стандартную структуру экрана Material Design:

```
┌────────────────────────────────────────────────────────┐
│ AppBar (Заголовок, кнопка меню, иконки действий)      │
├────────────────────────────────────────────────────────┤
│                                                        │
│ Body (Основная рабочая область экрана)                 │
│                                                        │
│                                  ┌──────────────────┐  │
│                                  │ FloatingAction-  │  │
│                                  │ Button (FAB)     │  │
│                                  └──────────────────┘  │
├────────────────────────────────────────────────────────┤
│ BottomNavigationBar (Нижняя панель переключения вкладок)│
└────────────────────────────────────────────────────────┘
```

### Пример комплексного каркаса экрана

```dart
class HomeScreen extends StatelessWidget {
  const HomeScreen({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: const Text('Каталог курсов'),
        actions: [
          IconButton(
            icon: const Icon(Icons.search),
            onPressed: () {},
          ),
        ],
      ),
      drawer: const Drawer(
        child: Center(child: Text('Боковое навигационное меню')),
      ),
      body: const Center(
        child: Text('Основной контент страницы'),
      ),
      floatingActionButton: FloatingActionButton(
        onPressed: () {},
        child: const Icon(Icons.add),
      ),
      bottomNavigationBar: BottomNavigationBar(
        items: const [
          BottomNavigationBarItem(icon: Icon(Icons.home), label: 'Главная'),
          BottomNavigationBarItem(icon: Icon(Icons.person), label: 'Профиль'),
        ],
      ),
    );
  }
}
```

### Задания для закрепления

1. **Смена цвета статус-бара:** Настройте параметры `AppBar` так, чтобы он был прозрачным, а иконки темными.
2. **Центрированная плавающая кнопка:** Измените позицию кнопки действия через параметр `floatingActionButtonLocation: FloatingActionButtonLocation.centerDocked`.
