## 1. Иерархия представлений (View Tree) и фазы отрисовки

Экран мобильного приложения формируется в виде древовидной структуры объектов:

- **`View` (Виджет):** Одиночный визуальный компонент, занимающий прямоугольную область экрана (кнопка, текст, картинка). Он отвечает за собственную отрисовку и реакцию на события касания.
- **`ViewGroup` (Контейнер / Layout):** Невидимый базовый класс для контейнеров, содержащих другие дочерние объекты `View` и управляющих их взаимным геометрическим положением.

```
                    ┌─────────────────────────┐
                    │  ViewGroup (Контейнер)  │
                    └────────────┬────────────┘
         ┌───────────────────────┴───────────────────────┐
         ▼                                               ▼
┌──────────────────┐                           ┌──────────────────┐
│   View (Текст)   │                           │ ViewGroup (Ряд)  │
└──────────────────┘                           └─────────┬────────┘
                                      ┌──────────────────┴──────────────────┐
                                      ▼                                     ▼
                             ┌──────────────────┐                  ┌──────────────────┐
                             │  View (Картинка) │                  │  View (Кнопка)   │
                             └──────────────────┘                  └──────────────────┘
```

### Фазы отображения каждого кадра

Каждый контейнер рассчитывает положение своих потомков в три последовательные фазы:

1. **Measure (Измерение):** Определение желаемых размеров каждого элемента с учетом доступного пространства родителя.
2. **Layout (Размещение):** Расчет конкретных экранных координат `(left, top, right, bottom)` для каждого потомка.
3. **Draw (Отрисовка):** Непосредственный рендеринг пикселей на холсте GPU.

> [!WARNING]
> Чем глубже вложенность контейнеров друг в друга, тем больше времени процессор тратит на фазы Measure и Layout, что приводит к задержкам и падению плавности анимаций ниже 60–120 FPS.

## Тема 1. LinearLayout: линейное распределение и веса

`LinearLayout` располагает дочерние элементы строго в один ряд: по вертикали или по горизонтали.

### Ключевые атрибуты

- `android:orientation="vertical | horizontal"` — направление главной оси раскладки.
- `android:gravity` — выравнивание содержимого **внутри** самого элемента.
- `android:layout_gravity` — выравнивание самого элемента **внутри** его родителя.
- `android:layout_weight` — коэффициент распределения свободного экранного пространства.

### Механика распределения весов (layout_weight)

Когда элементам задан `layout_weight`, их базовый размер вдоль главной оси **обязан** быть равен `0dp`. Это отключает предварительный замер и заставляет контейнер делить пространство пропорционально коэффициентам.

```xml
<!-- Схема: 2 кнопки в пропорции 1 к 2 -->
<!-- [ Кнопка 1 (1/3) ] [      Кнопка 2 (2/3)      ] -->

<LinearLayout xmlns:android="http://schemas.android.com/apk/res/android"
    android:layout_width="match_parent"
    android:layout_height="wrap_content"
    android:orientation="horizontal"
    android:weightSum="3"
    android:padding="16dp">

    <Button
        android:id="@+id/btnCancel"
        android:layout_width="0dp"
        android:layout_height="wrap_content"
        android:layout_weight="1"
        android:text="Отмена"
        android:layout_marginEnd="8dp" />

    <Button
        android:id="@+id/btnSubmit"
        android:layout_width="0dp"
        android:layout_height="wrap_content"
        android:layout_weight="2"
        android:text="Подтвердить заказ" />

</LinearLayout>
```

### Задания для закрепления

1. **Клавиатура пин-кода (Ряд кнопок):** Создайте горизонтальный `LinearLayout`, содержащий три круглые кнопки с цифрами `1`, `2`, `3`, равномерно распределенные по ширине экрана (`weight="1"` для каждой).
2. **Сплит-экран 50/50:** Создайте вертикальный `LinearLayout`, разделенный на две равные половины: верхняя синяя область и нижняя белая.
3. **Поле поиска с кнопкой:** Сверстайте ряд: текстовое поле ввода занимает всё оставшееся пространство экрана, а иконка-лупа справа имеет фиксированную ширину `48dp`.
4. **Центрирование заголовка:** Создайте вертикальный контейнер, где заголовок центрируется по горизонтали через `android:layout_gravity="center_horizontal"`, а подзаголовок прижат к правому краю.
5. **Форма входа с разделителем:** Сверстайте два поля ввода, между которыми расположен тонкий серый разделитель высотой `1dp` (`<View android:layout_height="1dp" android:background="#E0E0E0" />`).

## Тема 2. FrameLayout: наложение слоев и контейнеры фрагментов

`FrameLayout` предназначен для отображения одного дочернего элемента либо наложения нескольких элементов друг на друга слоями (по принципу стопки).

### Порядок наложения (Z-Index)

Элементы, объявленные в XML ниже по коду, отрисовываются поверх элементов, объявленных выше.

```xml
<!-- Схема наложения: Индикатор загрузки поверх карточки -->
<!-- ┌──────────────────────────┐ -->
<!-- │ [Картинка товара]        │ -->
<!-- │       ┌─────────┐        │ -->
<!-- │       │ Спиннер │        │ <-- Поверх картинки -->
<!-- │       └─────────┘        │ -->
<!-- └──────────────────────────┘ -->

<FrameLayout xmlns:android="http://schemas.android.com/apk/res/android"
    android:layout_width="match_parent"
    android:layout_height="250dp"
    android:background="#FAFAFA">

    <!-- 1-й слой (снизу): Фоновое изображение -->
    <ImageView
        android:id="@+id/ivCover"
        android:layout_width="match_parent"
        android:layout_height="match_parent"
        android:scaleType="centerCrop"
        android:src="@drawable/sample_product" />

    <!-- 2-й слой: Полупрозрачное затемнение -->
    <View
        android:layout_width="match_parent"
        android:layout_height="match_parent"
        android:background="#4D000000" />

    <!-- 3-й слой: Спиннер загрузки строго по центру -->
    <ProgressBar
        android:id="@+id/progressBar"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:layout_gravity="center" />

    <!-- 4-й слой (сверху): Бейджик скидки в правом верхнем углу -->
    <TextView
        android:id="@+id/tvBadge"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:layout_gravity="top|end"
        android:layout_margin="16dp"
        android:background="#E53935"
        android:textColor="#FFFFFF"
        android:padding="6dp"
        android:text="-30%" />

</FrameLayout>
```

### Задания для закрепления

1. **Аватар с бейджем статуса «Онлайн»:** Разместите круглую фотографию пользователя, а в её правом нижнем углу наложите зеленый круглый индикатор активности.
2. **Кнопка с оверлеем блокировки:** Создайте кнопку подтверждения, поверх которой при отправке данных отображается круговой `ProgressBar`, а сама кнопка блокируется.
3. **Плавающая кнопка действия (FAB):** Разместите на экране большой текстовый блок, а в правом нижнем углу поверх текста закрепите круглую кнопку `+` с отступом `24dp` от краев.
4. **Контейнер под фрагмент:** Создайте пустой каркас `FrameLayout` с идентификатором `@+id/fragmentContainerView`, занимающий всю свободную область экрана под шапкой.
5. **Видео-превью с иконкой Play:** Наложите поверх картинки видеоролика полупрозрачную иконку воспроизведения треугольной формы, выровненную строго по центру.

## Тема 3. RelativeLayout: относительное позиционирование

`RelativeLayout` позиционирует элементы относительно краев самого родителя или относительно соседних дочерних элементов по их `android:id`.

### Атрибуты связи элементов

| Категория                 | Атрибут в XML                           | Описание назначения                            |
| :------------------------ | :-------------------------------------- | :--------------------------------------------- |
| **Относительно родителя** | `android:layout_alignParentTop`         | Прижать к верхней границе контейнера           |
|                           | `android:layout_alignParentBottom`      | Прижать к нижней границе контейнера            |
|                           | `android:layout_centerInParent`         | Центрировать по горизонтали и вертикали        |
|                           | `android:layout_centerVertical`         | Центрировать только по вертикальной оси        |
| **Относительно соседа**   | `android:layout_toRightOf` / `toEndOf`  | Разместить правее указанного элемента по ID    |
|                           | `android:layout_toLeftOf` / `toStartOf` | Разместить левее указанного элемента           |
|                           | `android:layout_below`                  | Разместить строго под указанным элементом      |
|                           | `android:layout_alignBaseline`          | Выровнять текст по базовой линии шрифта соседа |

### Пример кода (Пункт списка настроек)

```xml
<RelativeLayout xmlns:android="http://schemas.android.com/apk/res/android"
    android:layout_width="match_parent"
    android:layout_height="wrap_content"
    android:padding="16dp">

    <ImageView
        android:id="@+id/ivIcon"
        android:layout_width="32dp"
        android:layout_height="32dp"
        android:layout_centerVertical="true"
        android:src="@drawable/ic_wifi" />

    <TextView
        android:id="@+id/tvSettingTitle"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:layout_toEndOf="@id/ivIcon"
        android:layout_toStartOf="@id/switchToggle"
        android:layout_marginStart="16dp"
        android:text="Беспроводная сеть Wi-Fi"
        android:textSize="16sp"
        android:textStyle="bold" />

    <TextView
        android:id="@+id/tvSettingSubtitle"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:layout_below="@id/tvSettingTitle"
        android:layout_alignStart="@id/tvSettingTitle"
        android:text="Подключено к Campus_5G"
        android:textColor="#757575" />

    <androidx.appcompat.widget.SwitchCompat
        android:id="@+id/switchToggle"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:layout_alignParentEnd="true"
        android:layout_centerVertical="true" />

</RelativeLayout>
```

### Задания для закрепления

1. **Чат-сообщение с временем:** Сверстайте облачко входящего сообщения, где текст сообщения занимает левую часть, а время отправки («14:32») выровнено по правому нижнему краю относительно текста.
2. **Шапка экрана (TopAppBar):** Разместите кнопку «Назад» у левого края, кнопку «Настройки» у правого края, а заголовок экрана выровняйте строго по центру родителя.
3. **Карточка товара в каталоге:** Разместите фото товара слева, название товара сверху справа от фото, а цену — под названием, прижатой к нижней границе фото.
4. **Элемент списка музыки:** Иконка обложки трека, название песни, имя исполнителя под названием и кнопка добавления в избранное у правого края контейнера.
5. **Выравнивание по базовой линии:** Разместите крупную цифру цены (`28sp`) и рядом мелкую надпись валюты («руб./мес.», `14sp`), выровняв их через `android:layout_alignBaseline`.

## Тема 4. ConstraintLayout: плоская разметка и гибкие связи

`ConstraintLayout` — современный стандарт разметки Android. Он позволяет создавать сложные, плоские (без вложенности) и адаптивные интерфейсы любой конфигурации.

### Ключевые концепции

1. **Связи (Constraints):** Каждый элемент обязан иметь минимум 2 привязки: одну по горизонтали и одну по вертикали.
2. **Размер 0dp (`match_constraint`):** Означает «занять всё пространство, ограниченное заданными констрейнтами» (замена `match_parent`).
3. **Смещения (Bias):** Позволяет сместить элемент относительно центра (например, `layout_constraintHorizontal_bias="0.3"` сдвигает элемент на 30% от левого края).
4. **Цепочки (Chains):** Группа элементов, двусторонне связанных друг с другом, распределяется как единое целое (`spread`, `spread_inside`, `packed`).
5. **Направляющие (Guidelines):** Невидимые вспомогательные линии (в `dp` или в `%`).

### Пример разметки карточки с Guideline и DimensionRatio

```xml
<androidx.constraintlayout.widget.ConstraintLayout
    xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:app="http://schemas.android.com/apk/res-auto"
    android:layout_width="match_parent"
    android:layout_height="wrap_content"
    android:padding="16dp">

    <!-- Процентная вертикальная направляющая на 35% экрана -->
    <androidx.constraintlayout.widget.Guideline
        android:id="@+id/guideline35"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:orientation="vertical"
        app:layout_constraintGuide_percent="0.35" />

    <!-- Изображение занимает левые 35% экрана с соотношением 1:1 -->
    <ImageView
        android:id="@+id/ivProduct"
        android:layout_width="0dp"
        android:layout_height="0dp"
        app:layout_constraintDimensionRatio="1:1"
        app:layout_constraintStart_toStartOf="parent"
        app:layout_constraintEnd_toStartOf="@id/guideline35"
        app:layout_constraintTop_toTopOf="parent"
        android:src="@drawable/sample_product" />

    <TextView
        android:id="@+id/tvTitle"
        android:layout_width="0dp"
        android:layout_height="wrap_content"
        android:layout_marginStart="16dp"
        android:text="Смартфон Galaxy S26 Ultra"
        android:textSize="18sp"
        android:textStyle="bold"
        app:layout_constraintStart_toEndOf="@id/guideline35"
        app:layout_constraintEnd_toEndOf="parent"
        app:layout_constraintTop_toTopOf="@id/ivProduct" />

    <TextView
        android:id="@+id/tvPrice"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:layout_marginStart="16dp"
        android:text="99 990 ₽"
        android:textSize="20sp"
        android:textColor="#2E7D32"
        app:layout_constraintStart_toEndOf="@id/guideline35"
        app:layout_constraintTop_toBottomOf="@id/tvTitle"
        app:layout_constraintBottom_toTopOf="@id/btnBuy" />

    <Button
        android:id="@+id/btnBuy"
        android:layout_width="0dp"
        android:layout_height="wrap_content"
        android:layout_marginStart="16dp"
        android:text="В корзину"
        app:layout_constraintStart_toEndOf="@id/guideline35"
        app:layout_constraintEnd_toEndOf="parent"
        app:layout_constraintBottom_toBottomOf="@id/ivProduct" />

</androidx.constraintlayout.widget.ConstraintLayout>
```

### Задания для закрепления

1. **Квадратное изображение:** Сделайте баннер, который растягивается на всю ширину экрана (`width="0dp"`), а высоту рассчитывает автоматически в пропорции 16:9 с помощью `app:layout_constraintDimensionRatio="16:9"`.
2. **Упакованная цепочка (Packed Chain):** Свяжите заголовок и подзаголовок в вертикальную упакованную цепочку со смещением к верхней трети экрана (`app:layout_constraintVertical_bias="0.2"`).
3. **Ограничитель (Barrier):** Разместите две надписи разной длины слева (ФИО и Должность), создайте вертикальный `androidx.constraintlayout.widget.Barrier` справа от них и привяжите кнопку к этому барьеру.
4. **Процентное позиционирование:** Разместите кнопку авторизации так, чтобы она начиналась на 15% ширины экрана и заканчивалась на 85% (используя 2 Guideline).
5. **Групповое управление видимостью:** Добавьте 3 элемента разметки в тег `<androidx.constraintlayout.widget.Group>` и скройте их одновременно одной строчкой в Java-коде через ID группы.

## Тема 5. Прокручиваемые контейнеры: ScrollView и HorizontalScrollView

Экран мобильного устройства ограничен по высоте. Если контент не помещается на дисплее (особенно при открытии экранной клавиатуры), нижняя часть интерфейса обрезается.

### Главные правила работы со ScrollView

1. `ScrollView` может содержать **ровно один прямой дочерний элемент** (обычно это `LinearLayout` или `ConstraintLayout`).
2. Для горизонтальной прокрутки используется `HorizontalScrollView`.
3. Чтобы фоновые кнопки прижимались к низу экрана на длинных дисплеях, обязательно добавляется атрибут `android:fillViewport="true"`.

```xml
<!-- Схема: Единственный ребенок внутри ScrollView -->
<!-- ScrollView -->
<!--   └── LinearLayout (orientation=vertical) -->
<!--         ├── Поле 1 -->
<!--         ├── Поле 2 -->
<!--         └── Кнопка -->

<ScrollView xmlns:android="http://schemas.android.com/apk/res/android"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    android:fillViewport="true">

    <LinearLayout
        android:layout_width="match_parent"
        android:layout_height="wrap_content"
        android:orientation="vertical"
        android:padding="24dp">

        <TextView
            android:layout_width="wrap_content"
            android:layout_height="wrap_content"
            android:text="Большая анкета регистрации"
            android:textSize="22sp"
            android:layout_marginBottom="16dp" />

        <EditText
            android:layout_width="match_parent"
            android:layout_height="wrap_content"
            android:hint="Фамилия"
            android:layout_marginBottom="12dp" />

        <EditText
            android:layout_width="match_parent"
            android:layout_height="wrap_content"
            android:hint="Имя"
            android:layout_marginBottom="12dp" />

        <EditText
            android:layout_width="match_parent"
            android:layout_height="wrap_content"
            android:hint="Отчество"
            android:layout_marginBottom="12dp" />

        <!-- Пустой заполнитель для выталкивания кнопки вниз -->
        <View
            android:layout_width="match_parent"
            android:layout_height="0dp"
            android:layout_weight="1" />

        <Button
            android:layout_width="match_parent"
            android:layout_height="wrap_content"
            android:text="Сохранить профиль" />

    </LinearLayout>

</ScrollView>
```

## Тема 6. Комбинирование разметок: include, merge и ViewStub

В реальных приложениях экраны собираются из переиспользуемых модулей: типовые шапки (Toolbar), нижние навигационные панели, карточки статусов и диалоги ошибок.

### Тег `<include>`: переиспользование разметки

Позволяет вставить готовую внешнюю разметку в любое место другого макета:

```xml
<!-- Вставка шапки экрана из файла layout_header.xml -->
<include
    android:id="@+id/customHeader"
    layout="@layout/layout_header"
    android:layout_width="match_parent"
    android:layout_height="wrap_content" />
```

### Тег `<merge>`: уничтожение лишних узлов

Если подключаемый файл сам обернут в `LinearLayout` или `FrameLayout`, при использовании `<include>` в дереве представлений возникает дублирующий контейнер. Замена корневого тега подключаемого файла на `<merge>` удаляет промежуточный уровень:

```xml
<!-- Файл: layout_user_actions.xml -->
<merge xmlns:android="http://schemas.android.com/apk/res/android">

    <Button
        android:id="@+id/btnLike"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="Нравится" />

    <Button
        android:id="@+id/btnShare"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="Поделиться" />

</merge>
```

### Тег `<ViewStub>`: отложенная ленивая загрузка

`ViewStub` — это невидимый элемент нулевого размера, который не расходует память на фазе запуска экрана. Он подгружает тяжелую разметку (например, экран поздравления с победой или детальную ошибку сети) только тогда, когда к нему явно обращаются из Java-кода.

```xml
<ViewStub
    android:id="@+id/stubNoInternet"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    android:layout="@layout/layout_no_internet_screen" />
```

Активация в коде Java:

```java
ViewStub stub = findViewById(R.id.stubNoInternet);
// Разметка загружается в память и отрисовывается только в этой строке:
View inflatedView = stub.inflate();
```

## Тема 7. Оптимизация верстки и борьба с Overdraw

### Сравнение контейнеров по производительности

| Контейнер                      | Сложность фазы Measure                  | Рекомендуемое применение                   | Риски для производительности                    |
| :----------------------------- | :-------------------------------------- | :----------------------------------------- | :---------------------------------------------- |
| **`FrameLayout`**              | \(O(1)\) — минимальная                  | Одиночные экраны, наложение слоев, оверлеи | Практически нет                                 |
| **`LinearLayout` (без весов)** | \(O(N)\) — линейная                     | Простые ряды из 2–4 элементов              | Нет                                             |
| **`LinearLayout` (с весами)**  | \(O(2N)\) — двукратный замер            | Пропорциональное деление кнопок            | При вложенности вес внутри веса дает \(O(2^d)\) |
| **`RelativeLayout`**           | \(O(2N)\) — замер по 2 осям             | Небольшие плоские блоки                    | Не рекомендуется вкладывать друг в друга        |
| **`ConstraintLayout`**         | Математический расчет системы уравнений | Сложные экраны любой геометрии             | Избыточен для простейших рядов из двух кнопок   |

### Проблема избыточной перерисовки (Overdraw)

Перерисовка возникает, когда система красит один и тот же пиксель экрана несколько раз за один кадр (например, фон окна -> фон ScrollView -> фон LinearLayout -> фон кнопки).

> [!TIP]
> **Как включить визуализацию перерисовки на смартфоне:**
> Откройте: `Настройки -> Для разработчиков -> Отладка GPU-перерисовки (Debug GPU Overdraw) -> Показывать зоны перерисовки`.
>
> - **Синий цвет:** 1 перерисовка (отлично).
> - **Зеленый цвет:** 2 перерисовки (норма).
> - **Розовый цвет:** 3 перерисовки (повод оптимизировать).
> - **Красный цвет:** 4+ перерисовок (критическая проблема скорости).
