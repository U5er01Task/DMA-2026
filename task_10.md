## 1. Глобальная анатомия проекта Flutter

После выполнения команды `flutter create my_app` генерируется типовое дерево директорий, объединяющее общий Dart-код, нативные платформенные обертки, конфигурационные файлы и тестовый контур:

```
my_app/
├── .dart_tool/                 <-- Служебные кэши сборщика Dart и генераторов кода
├── android/                    <-- Нативный проект Android (Gradle, Manifest, Java/Kotlin)
├── ios/                        <-- Нативный проект iOS (Xcode Workspace, CocoaPods, Swift)
├── web/                        <-- Обертка для Web (index.html, манифест PWA)
├── linux/ | macos/ | windows/  <-- Проекты для настольных операционных систем
├── lib/                        <-- 🎯 ОСНОВНОЙ ДАРТ-КОД ПРИЛОЖЕНИЯ (95% работы)
│   └── main.dart               <-- Точка входа в программу (функция main)
├── test/                       <-- Модульные, интеграционные и виджет-тесты
├── assets/ (создается вручную) <-- Шрифты, картинки, SVG, аудио, статические JSON
├── .gitignore                  <-- Список файлов, исключаемых из системы контроля версий
├── .metadata                   <-- Служебный файл Flutter CLI для отслеживания версий
├── analysis_options.yaml       <-- Правила статического анализатора и линтера кода
├── pubspec.yaml                <-- Паспорт приложения: зависимости, шрифты, метаданные
└── pubspec.lock                <-- Фиксатор точных версий скачанных библиотек
```

> [!IMPORTANT]
> Каталоги `.dart_tool/`, `build/`, а также сгенерированные файлы платформенных сборок никогда не коммитятся в Git. Они полностью воспроизводятся при выполнении команд `flutter pub get` и `flutter build`.

## Тема 1. Конфигуратор pubspec.yaml и управление ресурсами

Файл `pubspec.yaml` управляет именем приложения, версионированием, сторонними библиотеками (плагинами) и ресурсами (Assets).

### Версионирование приложения (Синтаксис semver)

Строка `version: 1.2.0+15` разделена знаком `+`:

- `1.2.0` — отображаемая версия (Version Name для пользователя / App Store).
- `15` — целочисленный номер сборки (Version Code для Google Play / Build Number).

### Пример конфигурации pubspec.yaml

```yaml
name: mobile_store_app
description: "Клиентское приложение интернет-магазина на Flutter"
publish_to: "none" # Запрет случайной публикации в публичный репозиторий pub.dev

version: 1.0.0+1

environment:
  sdk: ">=3.3.0 <4.0.0"

dependencies:
  flutter:
    sdk: flutter
  # Сторонние библиотеки из pub.dev (семантическое версионирование ^)
  cupertino_icons: ^1.0.8
  dio: ^5.4.1 # Сетевой клиент
  shared_preferences: ^2.2.2 # Локальное key-value хранилище
  intl: ^0.19.0 # Форматирование дат и чисел

dev_dependencies:
  flutter_test:
    sdk: flutter
  flutter_lints: ^3.0.0 # Рекомендованный набор правил линтера

flutter:
  uses-material-design: true

  # Регистрация статических ассетов
  assets:
    - assets/images/ # Регистрация целой папки с картинками
    - assets/icons/logo.svg # Регистрация конкретного файла
    - assets/mock_data.json # Локальные тестовые данные

  # Подключение кастомных шрифтов
  fonts:
    - family: RobotoCustom
      fonts:
        - asset: assets/fonts/Roboto-Regular.ttf
          weight: 400
        - asset: assets/fonts/Roboto-Bold.ttf
          weight: 700
```

> [!WARNING]
> Файл `pubspec.lock` фиксирует точные до последнего коммита версии библиотек, гарантируя одинаковую сборку у всех разработчиков команды. Его **обязательно** сохраняют в Git для конечных приложений.

### Задания для закрепления

1. **Регистрация каталога иконок:** Создайте директорию `assets/icons/` и подключите её в секцию `assets` файла `pubspec.yaml`.
2. **Управление версиями:** Измените версию приложения на номер `2.4.1` со сборочным кодом `35` и объясните разницу между ними.
3. **Подключение двух начертаний шрифта:** Скачайте бесплатный шрифт (например, `Montserrat`) и зарегистрируйте начертания `Regular` и `SemiBold` с соответствующими весами `weight: 400` и `weight: 600`.
4. **Локальная зависимость (Path dependency):** Подключите локальный модуль библиотеки из соседней папки через синтаксис `path: ../packages/core_kit`.
5. **Анализ pubspec.lock:** Выполните команду `flutter pub get` и найдите в `pubspec.lock` транзитивную зависимость библиотеки `dio`.

## Тема 2. Архитектура каталога lib: Layer-first vs Feature-first

Директория `lib/` содержит всю кодовую базу. При масштабировании проекта хаотичное складывание файлов в одну папку приводит к спагетти-коду. В коммерческой разработке применяются два базовых стандарта.

### Подход 1: Layer-first (Разделение по слоям)

Подходит для небольших утилит и компактных приложений (до 10–15 экранов).

```
lib/
├── main.dart
├── models/         <-- Все DTO и классы данных (User, Product, Order)
├── screens/        <-- Все экраны приложения (HomeScreen, CartScreen)
├── widgets/        <-- Общие переиспользуемые виджеты (CustomButton)
├── services/       <-- Сетевые вызовы и работа с базами данных
└── utils/          <-- Константы, хелперы, форматирование
```

### Подход 2: Feature-first (Разделение по фичам / функционалу)

Рекомендованный индустриальный стандарт для средних и крупных мобильных приложений (Clean Architecture / BLoC / Riverpod).

```
lib/
├── main.dart
├── core/                       <-- Ядро: общее для всего приложения
│   ├── network/                <-- Настройки Dio, перехватчики (Interceptors)
│   ├── theme/                  <-- Цветовые палитры, стили текста
│   ├── constants/              <-- Строковые константы, эндпоинты API
│   └── error/                  <-- Классы исключений (Failures, Exceptions)
│
└── features/                   <-- Модули независимых фичей
    ├── auth/                   <-- Фича авторизации
    │   ├── data/               <-- Источники данных (API, SharedPreferences)
    │   ├── domain/             <-- Бизнес-логика, сущности, Use Cases
    │   └── presentation/       <-- Экраны входа, виджеты форм, контроллеры/BLoC
    │
    └── catalog/                <-- Фича каталога товаров
        ├── data/
        ├── domain/
        └── presentation/
```

### Пример точки входа (lib/main.dart)

```dart
import 'package:flutter/material.dart';

void main() {
  // Гарантия инициализации биндингов движка Flutter перед стартом
  WidgetsFlutterBinding.ensureInitialized();
  runApp(const MainApplication());
}

class MainApplication extends StatelessWidget {
  const MainApplication({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Store App',
      debugShowCheckedModeBanner: false, // Отключение ленты DEBUG в углу
      theme: ThemeData(
        colorScheme: ColorScheme.fromSeed(seedColor: Colors.deepPurple),
        useMaterial3: true,
      ),
      home: const Scaffold(
        body: Center(child: Text('Базовый каркас инициализирован')),
      ),
    );
  }
}
```

### Задания для закрепления

1. **Каркас структуры Feature-first:** Создайте в папке `lib/features/` структуру подпапок для фичи `profile` (подпапки `data`, `domain`, `presentation`).
2. **Модуль ядра приложения (core):** Вынесите все текстовые константы API-адресов в файл `lib/core/constants/api_constants.dart`.
3. **Изоляция темы приложения:** Создайте класс `AppTheme` в `lib/core/theme/` с методами возврата светлой и темной темы `ThemeData`.
4. **Устранение жестких зависимостей:** Реорганизуйте проект: разделите экраны и их приватные виджеты так, чтобы приватные виджеты лежали в папке `presentation/widgets/`.
5. **Экспорт через барели (Barrel files):** Создайте файл `lib/features/auth/auth.dart`, экспортирующий наружу только публичные контракты фичи через оператор `export`.

## Тема 3. Нативные платформенные каталоги: android и ios

Flutter компилирует Dart-код в машинные инструкции, но хостится внутри нативного платформенного контейнера.

```
       Flutter Engine (lib/main.dart)
                     │
         Platform Channels / FFI
                     │
        ┌────────────┴────────────┐
        ▼                         ▼
  Android Container          iOS Container
 (android/app/src/...)      (ios/Runner/...)
```

### Разбор каталога `android/`

- `android/app/build.gradle` (или `build.gradle.kts`): задает `applicationId` (уникальный пакет в Google Play), `minSdkVersion` (минимум API 21+), `targetSdkVersion` и правила подписи ключами (`signingConfigs`).
- `android/app/src/main/AndroidManifest.xml`: системные разрешения (`INTERNET`, `CAMERA`) и конфигурация стартовой `MainActivity`.
- `android/app/src/main/res/`: нативные иконки лаунчера (`mipmap-*`) и ресурсы сплэш-скрина.

### Разбор каталога `ios/`

- `ios/Runner.xcworkspace`: файл проекта для открытия в среде Apple Xcode.
- `ios/Runner/Info.plist`: файл разрешений iOS (описания доступа к камере `NSCameraUsageDescription`, геолокации, настройки ориентации).
- `ios/Podfile`: конфигурация менеджера нативных зависимостей CocoaPods.

### Автоматизация через плагины экосистемы

Вместо ручного перекладывания десятков иконок по папкам разрешений используются инструменты:

1. `flutter_launcher_icons`: пакет, генерирующий адаптивные иконки для Android и iOS из одного исходного PNG размером 1024x1024.
2. `flutter_native_splash`: пакет, настраивающий экран мгновенного нативного запуска (до прогрева виртуальной машины Dart).

### Задания для закрепления

1. **Смена идентификатора пакета:** Измените `applicationId` в `android/app/build.gradle` на формат `ru.university.myapp`.
2. **Доступ к сети в Android Manifest:** Добавьте разрешение `<uses-permission android:name="android.permission.INTERNET"/>` в файл манифеста.
3. **Ограничение минимальной версии Android:** Поднимите уровень `minSdkVersion` до 24 в сборочном скрипте Gradle.
4. **Описание разрешения iOS:** Добавьте в `Info.plist` строковый ключ `NSPhotoLibraryUsageDescription` с текстом обоснования для пользователя.
5. **Генерация иконок через плагин:** Сконфигурируйте секцию `flutter_launcher_icons` в `pubspec.yaml` и запустите команду генерации `dart run flutter_launcher_icons`.

## Тема 4. Статический анализ и качество кода: analysis_options.yaml

Файл `analysis_options.yaml` управляет поведением компилятора Dart, предотвращая неочевидные баги и формируя единый командный стиль кода.

### Пример промышленной конфигурации

```yaml
include: package:flutter_lints/flutter.yaml

analyzer:
  # Исключение сгенерированных файлов из проверки анализатором
  exclude:
    - "**/*.g.dart"
    - "**/*.freezed.dart"
    - "build/**"

  # Режим строгой типизации (Dart Strict Mode)
  language:
    strict-casts: true # Запрет неявного приведения dynamic к конкретным типам
    strict-inference: true # Запрет вывода типа dynamic при отсутствии подсказок
    strict-raw-types: true # Запрет использования обобщенных типов без параметров (List вместо List<T>)

linter:
  rules:
    - prefer_const_constructors # Требовать const у виджетов где возможно
    - prefer_const_declarations # Использовать const вместо final для литералов
    - avoid_print # Запрет использования print() в продакшене
    - unawaited_futures # Запрет вызова Future без await или unawaited()
    - always_declare_return_types # Всегда указывать тип возвращаемого значения
    - cancel_subscriptions # Контроль закрытия StreamSubscription
    - close_sinks # Контроль закрытия StreamController
    - prefer_final_locals # Локальные переменные должны быть final
```

### Задания для закрепления

1. **Включение правила prefer_const_constructors:** Активируйте правило и проверьте, как анализатор подчеркивает виджеты без ключевого слова `const`.
2. **Защита от сырых типов (strict-raw-types):** Включите строгую типизацию и исправьте ошибки в объявлении переменных вида `List items = [];`.
3. **Блокировка console.log / print:** Активируйте правило `avoid_print` и замените все вызовы `print` на библиотечный логгер `debugPrint()` или пакет `logger`.
4. **Исключение служебных папок:** Добавьте в блок `analyzer.exclude` пути к сгенерированным локализациям.
5. **Проверка проекта через консоль:** Запустите полную проверку кодовой базы через терминал командой `flutter analyze` и добейтесь статуса `No issues found!`.

## Тема 5. Разделение окружений сборки (Flavors) и директория test

В коммерческой разработке приложение существует минимум в двух версиях: **Development (Dev)** со стендовыми серверами и тестовой базой данных, и **Production (Prod)** с реальными платежами и пользователями.

### Способ 1: Использование независимых точек входа и `--dart-define`

Создаются раздельные файлы запуска:

- `lib/main_dev.dart`
- `lib/main_prod.dart`

Команда сборки:

```bash
flutter run -t lib/main_dev.dart --dart-define=BASE_URL=https://dev.api.store.ru
flutter run -t lib/main_prod.dart --dart-define=BASE_URL=https://api.store.ru
```

Чтение переменной в коде:

```dart
const String apiBaseUrl = String.fromEnvironment(
  'BASE_URL',
  defaultValue: 'https://dev.api.store.ru',
);
```

### Организация директории `test/`

В папке `test/` зеркалируется структура папки `lib/`:

```
test/
├── unit/                       <-- Тесты чистых функций и вычислений
│   └── price_calculator_test.dart
├── widget/                     <-- Тесты интерфейсных компонентов
│   └── custom_button_test.dart
└── mocks/                      <-- Поддельные сетевые ответы и заглушки
```

### Задания для закрепления

1. **Создание раздельных точек входа:** Создайте файлы `lib/main_dev.dart` и `lib/main_prod.dart`, запускающие приложение с разным заголовком в AppBar.
2. **Чтение флага через String.fromEnvironment:** Считайте строковый ключ API-ключа из параметров сборки с предоставлением значения по умолчанию.
3. **Написание первого Unit-теста:** В папке `test/` напишите тест функции сложения стоимости корзины с помощью метода `test()` и матчера `expect()`.
4. **Виджет-тест экрана:** С помощью функции `testWidgets()` проверьте наличие текста на экране и нажатие на кнопку через `tester.tap()`.
5. **Запуск тестов из командной строки:** Запустите прогон всех тестов проекта командой `flutter test` с выводом покрытия кода.

## 50 Смешанных заданий по структуре и конфигурации проектов

Задания охватывают реальные задачи настройки мобильных проектов перед публикацией в магазины приложений (App Store, Google Play, RuStore).

### Блок 1: Конфигурация ресурсов, шрифтов и pubspec.yaml (1–10)

1. **Каталог масштабируемых изображений (Density-aware):** Настройте структуру ассетов с коэффициентами плотности: `assets/images/logo.png`, `assets/images/2.0x/logo.png`, `assets/images/3.0x/logo.png`.
2. **Конфигурация темной и светлой темы шрифтов:** Подключите семейство шрифтов с раздельными начертаниями для стилей `italic` и `normal`.
3. **Локальный пакет шрифта:** Настройте подключение шрифта из изолированного локального пакета проекта.
4. **Подключение видеофайла в ассеты:** Зарегистрируйте MP4-видеоролик в `pubspec.yaml` для фонового экрана авторизации.
5. **Пакетирование звуковых эффектов:** Сконфигурируйте папку `assets/audio/` для хранения звуков нажатия кнопок.
6. **Очистка от неиспользуемых зависимостей:** Проанализируйте `pubspec.yaml` и удалите избыточные библиотеки с помощью утилиты `dart pub deps`.
7. **Переопределение зависимостей (dependency_overrides):** Зафиксируйте конкретную версию конфликтующей транзитивной библиотеки через блок переопределения.
8. **Внедрение векторных SVG-ассетов:** Настройте папку векторной графики и подключите библиотеку `flutter_svg`.
9. **Загрузка тестового JSON-файла:** Напишите метод чтения файла `rootBundle.loadString('assets/mock.json')` с обработкой ошибок.
10. **Версионирование для RuStore и Google Play:** Настройте схему генерации `versionCode` на основе таймстемпа сборки.

### Блок 2: Архитектура директорий Feature-first и Clean Architecture (11–20)

11. **Иерархия фичи корзины покупок:** Спроектируйте дерево папок для фичи `cart` со слоями `data`, `domain`, `presentation`.
12. **Выделение слоя данных (Data Layer):** Создайте подпапки `datasources` (удаленный и локальный источник), `models` (DTO) и `repositories`.
13. **Выделение слоя бизнес-логики (Domain Layer):** Создайте подпапки `entities` (чистые модели), `repositories` (абстрактные интерфейсы) и `usecases`.
14. **Модуль сетевого клиента (Core Network):** Спроектируйте модуль с базовым классом сетевого клиента, перехватчиком токенов и обработчиком таймаутов.
