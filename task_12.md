## 1. Подсистема AssetBundle и механизм сборки ресурсов

Во Flutter статические ресурсы не зашиваются напрямую в бинарный исполняемый файл приложения, а упаковываются в специальный контейнер ресурсов — **AssetBundle**.

При сборке инструментарий Flutter формирует бинарный реестр `AssetManifest.bin` (или JSON в веб-сборках), где каждому строковому пути сопоставляются его физические копии разного разрешения.

```
                    ┌───────────────────────────────────┐
                    │      Файловая система assets/     │
                    └─────────────────┬─────────────────┘
                                      │ flutter build
                                      ▼
                    ┌───────────────────────────────────┐
                    │            AssetBundle            │
                    ├───────────────────────────────────┤
                    │ • AssetManifest.bin (Реестр путей)│
                    │ • FontManifest.json (Шрифты)      │
                    │ • Сжатые бинарные файлы ресурсов  │
                    └─────────────────┬─────────────────┘
                                      │
         ┌────────────────────────────┴────────────────────────────┐
         ▼                                                         ▼
┌──────────────────┐                                     ┌──────────────────┐
│ rootBundle       │                                     │ DefaultAssetBundle│
│ (Глобальный I/O) │                                     │ (Привязан к UI)  │
└──────────────────┘                                     └──────────────────┘
```

## Тема 1. Растровая графика и учет плотности экранов (Density-aware Assets)

Мобильные экраны имеют разную плотность пикселей на дюйм (DPI / Device Pixel Ratio). Если на экране с коэффициентом `3.0x` отобразить маленькую картинку `1.0x`, она станет размытой. Если везде использовать картинки `3.0x`, память старых бюджетных телефонов переполнится (Out Of Memory Crash).

### Структура подпапок плотности

Flutter автоматически выбирает оптимальный файл по правилу именования подпапок:

```
assets/
└── images/
    ├── banner.png          <-- Базовый размер 1.0x (например, 200x100 px)
    ├── 2.0x/
    │   └── banner.png      <-- Размер 2.0x (400x200 px)
    └── 3.0x/
        └── banner.png      <-- Размер 3.0x (600x300 px)
```

Регистрация в `pubspec.yaml`:
Достаточно зарегистрировать только базовую родительскую папку:

```yaml
flutter:
  assets:
    - assets/images/
```

### Пример использования и оптимизация памяти

```dart
import 'package:flutter/material.dart';

class ProductImageWidget extends StatelessWidget {
  const ProductImageWidget({super.key});

  @override
  Widget build(BuildContext context) {
    return Image.asset(
      'assets/images/banner.png',
      width: 200,
      height: 100,
      fit: BoxFit.cover,

      // КРИТИЧЕСКАЯ ОПТИМИЗАЦИЯ ПАМЯТИ:
      // Принудительное декодирование в меньший буфер GPU
      cacheWidth: 400, // Пиксели для отрисовки (с учетом 2x плотности)

      // Плейсхолдер при медленном чтении из хранилища
      frameBuilder: (context, child, frame, wasSynchronouslyLoaded) {
        if (wasSynchronouslyLoaded || frame != null) {
          return child;
        }
        return const Center(child: CircularProgressIndicator());
      },

      // Защита от отсутствующих ассетов
      errorBuilder: (context, error, stackTrace) {
        return const Icon(Icons.broken_image, size: 50, color: Colors.grey);
      },
    );
  }
}
```

### Задания для закрепления

1. **Создание иерархии плотностей:** Подготовьте тестовое изображение в трех разрешениях (100x100, 200x200, 300x300) и разместите их по папкам `1.0x`, `2.0x`, `3.0x`.
2. **Эксперимент с плотностью эмулятора:** Запустите приложение на эмуляторах с разным DPR (например, mdpi и xxhdpi) и проверьте через логи, какой конкретно файл загружается.
3. **Оптимизация через cacheWidth:** Продемонстрируйте снижение потребления оперативной памяти при загрузке 4K-картинки в иконку размером 50x50 с помощью параметра `cacheWidth`.
4. **Овальный аватар из ассета:** Отобразите изображение внутри виджета `CircleAvatar` с использованием провайдера `AssetImage`.
5. **Безопасная обработка сбоев:** Сделайте намеренную ошибку в пути файла и настройте показ красивого виджета-заглушки через `errorBuilder`.

## Тема 2. Векторная графика (SVG) и микро-анимации Lottie

Графический движок Flutter (Impeller / Skia) из соображений производительности не имеет встроенного парсера XML-структуры SVG. Для векторных изображений и сложных векторных анимаций используются специализированные библиотеки.

### Пакет flutter_svg (Векторные иконки и иллюстрации)

Векторная графика идеальна для иконок и логотипов, так как сохраняет идеальную резкость на любых экранах и весит в десятки раз меньше PNG.

```yaml
dependencies:
  flutter_svg: ^2.0.10+1
```

```dart
import 'package:flutter/material.dart';
import 'package:flutter_svg/flutter_svg.dart';

Widget buildLogo() {
  return SvgPicture.asset(
    'assets/icons/app_logo.svg',
    width: 64,
    height: 64,
    // Динамическая перекраска векторных слоев под цвет темы
    colorFilter: const ColorFilter.mode(Colors.deepPurple, BlendMode.srcIn),
    semanticsLabel: 'Фирменный логотип сервиса',
  );
}
```

### Пакет lottie (Интерактивные векторные анимации After Effects)

Анимации Lottie передаются дизайнерами в компактном формате JSON, экспортированном из Adobe After Effects.

```yaml
dependencies:
  lottie: ^3.1.0
```

```dart
import 'package:flutter/material.dart';
import 'package:lottie/lottie.dart';

class SuccessAnimationView extends StatefulWidget {
  const SuccessAnimationView({super.key});

  @override
  State<SuccessAnimationView> createState() => _SuccessAnimationViewState();
}

class _SuccessAnimationViewState extends State<SuccessAnimationView>
    with SingleTickerProviderStateMixin {
  late final AnimationController _controller;

  @override
  void initState() {
    super.initState();
    _controller = AnimationController(vsync: this);
  }

  @override
  void dispose() {
    _controller.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return Lottie.asset(
      'assets/animations/order_success.json',
      controller: _controller,
      onLoaded: (composition) {
        // Установка длительности из файла анимации и запуск
        _controller
          ..duration = composition.duration
          ..forward();
      },
    );
  }
}
```

### Задания для закрепления

1. **Подключение SVG-иконки:** Подключите библиотеку `flutter_svg`, добавьте SVG-файл в `pubspec.yaml` и выведите его на экран.
2. **Адаптивная перекраска SVG:** Реализуйте переключение цвета SVG-иконки (белый в темной теме, черный в светлой) через `ColorFilter.mode`.
3. **Зацикленная анимация загрузки:** Скачайте бесплатную Lottie-анимацию спиннера и настройте её бесконечное воспроизведение (`repeat: true`).
4. **Управление анимацией по кнопке:** Настройте запуск Lottie-анимации «Лайк» только при нажатии пользователем на карточку.
5. **Индикатор прогресса по тапу:** Свяжите контроллер Lottie с ползунком `Slider`, управляя прогрессом анимации вручную через `_controller.value`.

## Тема 3. Типографика: шрифты, начертания и кастомные иконки

Шрифты придают мобильному приложению индивидуальность и формируют визуальную иерархию бренда.

### Декларация шрифтов в pubspec.yaml

```yaml
flutter:
  fonts:
    - family: InterBrand
      fonts:
        - asset: assets/fonts/Inter-Regular.ttf
          weight: 400
        - asset: assets/fonts/Inter-SemiBold.ttf
          weight: 600
        - asset: assets/fonts/Inter-Bold.ttf
          weight: 700
        - asset: assets/fonts/Inter-Italic.ttf
          style: italic
```

### Применение шрифта в кодовой базе

```dart
// Способ 1: Локально в конкретном текстовом блоке
const textStyle = TextStyle(
  fontFamily: 'InterBrand',
  fontWeight: FontWeight.w600,
  fontSize: 18,
);

// Способ 2: Глобально для всего приложения через тему (Рекомендуется)
ThemeData buildAppTheme() {
  return ThemeData(
    useMaterial3: true,
    fontFamily: 'InterBrand', // Применяется ко всем Text() автоматически
    textTheme: const TextTheme(
      headlineLarge: TextStyle(fontWeight: FontWeight.w700, fontSize: 32),
      bodyMedium: TextStyle(fontWeight: FontWeight.w400, fontSize: 16),
    ),
  );
}
```

> [!WARNING]
> Использование пакета `google_fonts` без предварительной локальной упаковки шрифтов в продакшене приводит к риску: при запуске приложения без доступа в интернет шрифты не смогут скачаться, и система откатится к стандартному системному шрифту (шрифтовой скачок / FOIT).

### Задания для закрепления

1. **Подключение семейства шрифтов:** Зарегистрируйте в проекте локальный шрифт с тремя начертаниями (Light, Regular, Bold).
2. **Создание кастомного шрифта иконок (IconFont):** Сгенерируйте с помощью сервиса FlutterIcon шрифт из 5 своих SVG и выведите иконку через класс `Icon(IconData(0xe800, fontFamily: 'MyIcons'))`.
3. **Настройка резервного шрифта (Font Fallback):** Настройте в `TextStyle` параметр `fontFamilyFallback: ['Roboto', 'Arial']` на случай отсутствия редких символов.
4. **Глобальная смена шрифта приложения:** Настройте переключение шрифта интерфейса во время работы приложения через провайдер состояния.
5. **Форматирование цифр фиксированной ширины:** Включите табличные цифры моноширинного отображения с помощью `fontFeatures: [FontFeature.tabularFigures()]` для экрана таймера.

## Тема 4. Текстовые и бинарные ресурсы: rootBundle и чтение файлов

Кроме визуальных ассетов, приложению требуются конфигурационные файлы, локальные географические справочники, списки городов и предобученные ML-модели.

### Способы чтения ассетов

| Метод чтения                     | Возвращаемый тип   | Назначение                                                            |
| :------------------------------- | :----------------- | :-------------------------------------------------------------------- |
| `rootBundle.loadString(path)`    | `Future<String>`   | Текстовые файлы: JSON, XML, CSV, TXT, конфиги                         |
| `rootBundle.load(path)`          | `Future<ByteData>` | Бинарные файлы: базы данных `.sqlite`, аудио `.mp3`, модели `.tflite` |
| `DefaultAssetBundle.of(context)` | `AssetBundle`      | Контекстно-зависимый бандл (позволяет подменять данные в Unit-тестах) |

### Пример кода (Чтение локального JSON и бинарной базы данных)

```dart
import 'dart:convert';
import 'package:flutter/services.dart';

class LocalAssetRepository {
  // 1. Чтение текстового JSON-файла
  Future<List<String>> loadCitiesList() async {
    try {
      final String jsonString = await rootBundle.loadString('assets/data/cities.json');
      final List<dynamic> decoded = jsonDecode(jsonString);
      return decoded.map((item) => item['name'] as String).toList();
    } catch (e) {
      print("Ошибка чтения файла ассетов: $e");
      return [];
    }
  }

  // 2. Чтение бинарного файла для копирования во внутреннюю память
  Future<Uint8List> loadPrepopulatedDatabase() async {
    final ByteData byteData = await rootBundle.load('assets/db/prepopulated.db');
    // Преобразование байтов для последующей записи в каталог getApplicationDocumentsDirectory()
    return byteData.buffer.asUint8List();
  }
}
```

### Задания для закрепления

1. **Чтение файла политики конфиденциальности:** Разместите в `assets/docs/privacy.txt` большой текст договора и отобразите его в прокручиваемом виджете `SingleChildScrollView`.
2. **Парсер списка регионов:** Создайте JSON со списком областей и городов. Распарсите его в строго типизированные модели при старте экрана.
3. **Копирование базы данных из ассетов:** Напишите метод, проверяющий наличие локального файла SQLite в памяти устройства и копирующий его из ассетов при первом запуске.
4. **Контекстный DefaultAssetBundle:** Замените `rootBundle` на `DefaultAssetBundle.of(context)` и объясните, почему это повышает тестируемость кода.
5. **Чтение бинарного аудиофайла:** Загрузите байты звукового эффекта из папки `assets/audio/click.mp3` и выведите его размер в килобайтах.

## Тема 5. Типобезопасность ассетов (FlutterGen) и предзагрузка (Precaching)

### Проблема хардкода строковых путей

Написание путей вручную `'assets/images/home_baner.png'` чревато ошибками: опечатка в одной букве не будет обнаружена компилятором и приведет к крашу интерфейса у конечного пользователя.

### Решение: Пакет FlutterGen (Кодогенерация ассетов)

Пакет сканирует папку `assets/` и автоматически генерирует типизированный класс Dart.

```yaml
dev_dependencies:
  build_runner: ^2.4.8
  flutter_gen_runner: ^5.4.0
```

Генерация запускается командой: `dart run build_runner build`

Использование сгенерированного кода:

```dart
// Вместо небезопасной строки: Image.asset('assets/images/user_avatar.png')
// Используется строго типизированный доступ компилятора:
Widget avatar = Assets.images.userAvatar.image(width: 48, height: 48);
SvgPicture logo = Assets.icons.brandLogo.svg();
```

### Устранение белого мигания через precacheImage

Когда экран с тяжелой картинкой открывается впервые, движку требуется несколько кадров на чтение файла с диска и декодирование. В этот момент пользователь видит белую вспышку или серый фон.

```dart
class SplashScreen extends StatefulWidget {
  const SplashScreen({super.key});

  @override
  State<SplashScreen> createState() => _SplashScreenState();
}

class _SplashScreenState extends State<SplashScreen> {
  @override
  void didChangeDependencies() {
    super.didChangeDependencies();

    // Предварительный прогрев кэша изображений в оперативной памяти:
    precacheImage(const AssetImage('assets/images/heavy_background.jpg'), context);
  }

  @override
  Widget build(BuildContext context) {
    return const Scaffold(body: Center(child: Text("Загрузка ресурсов...")));
  }
}
```

### Задания для закрепления

1. **Настройка FlutterGen:** Подключите `flutter_gen_runner` и сгенерируйте класс `Assets` для своего набора картинок.
2. **Эксперимент с белым миганием:** Смоделируйте медленный переход на экран с тяжелой фотографией и устраните задержку отрисовки через `precacheImage`.
3. **Предзагрузка векторного SVG:** Используйте метод `precachePicture` из пакета `flutter_svg` для предварительного прогрева векторного логотипа.
4. **Конфигурация flutter_gen.yaml:** Настройте интеграцию генератора со стилем интеграции виджетов в корневом конфигураторе `build.yaml`.
5. **Проверка несуществующего пути:** Убедитесь, что при удалении картинки из папки генератор немедленно выдает ошибку компиляции в местах её старого использования.
